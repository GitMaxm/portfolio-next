# Портфолио

Сайт-портфолио фронтенд-разработчика. Публичная часть показывает проекты
и навыки, локальная админка их редактирует.

Next.js 16 (App Router) · TypeScript (strict) · SCSS-модули · Feature-Sliced Design

## Запуск

Нужен Node 22. Для кнопки «Снять скриншот сайта» в админке — ещё установленный Google Chrome.

```bash
nvm use 22
npm install
```

Контент лежит в `content/portfolio.json`, отдаёт его json-server. Запускать два процесса в разных терминалах:

```bash
npm run json-server   # API на :3001
npm run dev           # сайт на :3000
```

Без json-server страницы с проектами и навыками вернут ошибку.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm run build` / `start` | прод-сборка и её запуск |
| `npm run json-server` | API из `content/portfolio.json` |
| `npm run check` | типы, ESLint и слои FSD; по отдельности — `typecheck`, `lint`, `lint:fsd` |
| `npm run fix` | автофикс ESLint |
| `npm run images:prune` | неиспользуемые картинки проектов; `-- --yes` — удалить |
| `npm run og` | пересобрать OG-обложку `public/img/og/cover.png` |

Pre-commit хук прогоняет файлы коммита через `eslint --fix`, затем запускает
`typecheck` и `lint:fsd`. Если хук упал, коммит не создаётся.

## Структура

```
content/         контент сайта: проекты и навыки
public/          картинки, иконки, robots.txt
scripts/         уборка картинок, OG-обложка
src/
  app/           роуты Next.js, глобальные стили
  widgets/       main: about · footer · header · navbar · preview-projects · skills
                 admin: dashboard · sidebar
  features/      main: project-filter
                 admin: project-manager · skill-manager
  entities/      project · skill
  shared/        api · config · lib · model · styles · ui
```

## Архитектура

[Feature-Sliced Design](https://fsd.how/ru). Импортировать можно только вниз по слоям:

```
app → widgets → features → entities → shared
```

Импорт между слайсами одного слоя запрещён. Внутри слайса код разложен
по сегментам: `ui`, `model` (типы, хуки, состояние), `api`, `lib`, `config`.

Наружу слайс выставляет только `index.ts`:

```ts
import { SkillCard } from '@/entities/main/skill';              // да
import { SkillCard } from '@/entities/main/skill/ui/SkillCard'; // нет
```

В `index.ts` попадает только то, чем пользуются снаружи. Клиентские хуки туда
не кладутся: серверная страница, импортируя слайс, затянула бы их в свой граф,
и сборка упала бы.

Отдельного слоя `pages` нет — вёрстка страниц лежит в `src/app/**/page.tsx`.
Соблюдение слоёв проверяет `npm run lint:fsd`.

## Конвенции

Доменные типы — в `model/types.ts` слайса, пропсы компонента — в `types.ts` рядом с ним.

| | Правило | Пример |
|---|---|---|
| `type` | префикс `T` | `TSkillLevel` |
| `interface` | префикс `I` | `ISkillCardProps` |
| `enum` | SCREAMING_CASE | `LIST_VIEW_MODE` |

Свойства в типе: примитивы → массивы → объекты, необязательные в конце.

Обработчики: проп — `on*`, функция — `handle*`, действие называется одинаково:

```tsx
<SkillTable onDeleteClick={handleDeleteClick} />
```

Порядок внутри компонента: встроенные хуки → хуки с эффектами → переменные →
функции, между группами пустая строка. Пустая строка перед `return` и `if`.

Отступы — 2 пробела (`.editorconfig` и правило ESLint). Prettier не используется.

## Данные

Файл `content/portfolio.json`, коллекции `projects` и `skills`. Адрес API —
константа в `entities/*/api/`.

`id` новой записи назначает сервер, поэтому `addProject` и `addSkill`
принимают черновик без `id`.

## Как добавить навык

В админке, `/admin/skills/new`:

1. На [simpleicons.org](https://simpleicons.org) скопируйте SVG нужной технологии
   и вставьте целиком в поле «Иконка» — путь извлечётся сам.
2. Оттуда же возьмите фирменный цвет для поля «Цвет».
3. Заполните название, уровень и описание.

Иконка хранится строкой `d` одного `<path>`, цветом и `viewBox`. В разметку
попадает только атрибут `d`, поэтому вставить через это поле исполняемый код нельзя.

Иконки Simple Icons — CC0, но логотипы остаются товарными знаками своих владельцев.

## Как добавить проект

В админке, `/admin/projects/new`. Картинка нужна одна, любого размера и формата.
Её можно:

- перетащить в поле «Обложка»;
- снять автоматически: заполнить «Ссылку на проект» и нажать «Снять скриншот сайта».

Сервер обрежет картинку под обложку в списке (370 × 297) и под страницу проекта
(800 × 600), пережмёт в webp с двойной плотностью для retina и положит в
`public/img/projects/`. Имя файла — хэш содержимого, поэтому повторный снимок
того же сайта перезаписывает файл, а не создаёт копию.

Скриншот снимает `playwright-core` через системный Google Chrome — отдельный
браузер не скачивается. Если Chrome не установлен, кнопка сообщит об этом,
а перетаскивание продолжит работать.

Картинки, на которые больше никто не ссылается (обложку заменили, проект удалили),
остаются в папке. Убрать их:

```bash
npm run images:prune           # показать
npm run images:prune -- --yes  # удалить
```

Скрипт трогает только файлы, сохранённые админкой (`<название>-<хэш>.webp`),
картинки, добавленные вручную, он не удаляет.

## Как добавить слайс

На примере сущности:

```
src/entities/main/<название>/
  model/types.ts     доменные типы
  api/<название>Api.ts
  ui/<Компонент>.tsx
  ui/types.ts        пропсы компонентов
  index.ts           публичный API
```

После этого `npm run lint:fsd` проверит названия сегментов, публичный API
и импорты в обход `index.ts`.

## Ограничения

- Админка рассчитана только на локальный запуск: авторизации нет, картинки
  пишутся прямо в `public/`, скриншоты снимает локальный Chrome.
- Адрес API захардкожен (`http://localhost:3001`), переменных окружения нет.
