# Портфолио

Сайт-портфолио фронтенд-разработчика с админкой. Публичная часть показывает
проекты и навыки, админка позволяет их редактировать.

Next.js 16 (App Router) · TypeScript (strict) · SCSS-модули · Feature-Sliced Design

## Запуск

Нужен **Node 22**:

```bash
nvm use 22
npm install
```

Контент отдаёт мок-сервер, поэтому запускать нужно **два процесса** в разных терминалах:

```bash
npm run json-server   # API на :3001
npm run dev           # приложение на :3000
```

Без json-server страницы проектов и навыков вернут ошибку — данные тянутся с него на сервере.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm run build` | прод-сборка |
| `npm run start` | запуск собранного приложения |
| `npm run json-server` | мок-API из `mock/projectsTestTable.json` |
| `npm run check` | типы + ESLint + архитектура |
| `npm run fix` | автофикс ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` / `lint:fix` | ESLint |
| `npm run lint:fsd` | проверка слоёв через Steiger |

На `git commit` автоматически срабатывает pre-commit хук: файлы из коммита
прогоняются через `eslint --fix`, затем выполняются `typecheck` и `lint:fsd`.
Если хук упал — коммит не создан, исправьте и повторите. Обойти: `git commit --no-verify`.

## Структура

```
mock/            данные для json-server
public/          картинки, иконки, robots.txt
src/
  app/           роуты Next.js, глобальные стили
  widgets/       about · footer · header · navbar · preview-projects · skills · sidebar
  features/      project-filter · project-manager · skill-manager
  entities/      project · skill
  shared/        api · config · lib · model · styles · ui
```

Внутри `widgets`, `features` и `entities` слайсы разложены по разделам сайта:
`main/` — публичная часть, `admin/` — админка.

## Архитектура

[Feature-Sliced Design](https://fsd.how/ru). Порядок слоёв, импортировать можно **только вниз**:

```
app → widgets → features → entities → shared
```

`features` берёт из `entities` и `shared`; наоборот — нельзя. Импорт между
слайсами одного слоя тоже запрещён.

Внутри слайса код разложен по сегментам: `ui` (компоненты), `model`
(типы, хуки, состояние), `api` (запросы), `lib` (мелкая логика), `config` (константы).

Каждый слайс наружу выставляет только `index.ts`:

```ts
import { SkillCard } from '@/entities/main/skill';              // да
import { SkillCard } from '@/entities/main/skill/ui/SkillCard'; // нет
```

В `index.ts` попадает только то, чем пользуются снаружи. Клиентские хуки туда
класть нельзя: серверная страница, импортируя слайс, затянет их в свой граф и сборка упадёт.

Вёрстка страниц лежит прямо в `src/app/**/page.tsx` — отдельного слоя `pages` в проекте нет.

Всё перечисленное проверяется командой `npm run lint:fsd`.

## Конвенции

Типы лежат в отдельных файлах: доменные — в `model/types.ts` слайса,
пропсы компонента — в `types.ts` рядом с ним.

| | Правило | Пример |
|---|---|---|
| `type` | префикс `T` | `TSkillLevel` |
| `interface` | префикс `I` | `ISkillCardProps` |
| `enum` | SCREAMING_CASE | `LIST_VIEW_MODE` |

Порядок свойств в типе: примитивы → массивы → объекты, необязательные в конец.

Обработчики событий: проп — `on*`, функция — `handle*`, слово-действие одинаковое.

```tsx
<SkillTable onDeleteClick={handleDeleteClick} />
```

Порядок внутри компонента, между группами — пустая строка: встроенные хуки →
хуки с эффектами → локальные переменные → локальные функции. Пустая строка
перед `return` и `if`.

Отступы — 2 пробела, заданы в `.editorconfig` и продублированы правилом ESLint.
Prettier в проекте не используется.

## Данные

json-server, файл `mock/projectsTestTable.json`, коллекции `projects` и `skills`.
Адрес API задан константой в `entities/*/api/`.

При создании записи **`id` назначает сервер** и игнорирует присланный клиентом,
поэтому `addProject` и `addSkill` принимают черновик без `id`.

## Как добавить навык

Через админку, `/admin/skills/new`:

1. На [simpleicons.org](https://simpleicons.org) найдите нужную технологию,
   скопируйте SVG кнопкой на карточке и вставьте его целиком в поле «Иконка» —
   путь извлечётся сам, предпросмотр обновится сразу.
2. Там же скопируйте фирменный цвет и задайте его в поле «Цвет».
3. Заполните название, уровень и описание, нажмите «Создать».

Иконка хранится строкой `d` одиночного `<path>` плюс цвет и `viewBox` — файлы
нигде не лежат. В разметку попадает только атрибут `d`, поэтому вставить
исполняемый код через это поле нельзя.

Иконки Simple Icons распространяются под CC0. Логотипы остаются товарными
знаками владельцев: перечислять ими технологии можно, выдавать за свои — нет.

## Как добавить проект

Через админку, `/admin/projects/new`. Картинки в форме пока не редактируются:
файлы кладутся руками в `public/img/projects/`, а имена прописываются в
`mock/projectsTestTable.json` в поле `image`.

## Как добавить новый слайс

На примере сущности:

```
src/entities/main/<название>/
  model/types.ts     доменные типы
  api/<название>Api.ts
  ui/<Компонент>.tsx
  ui/types.ts        пропсы компонентов
  index.ts           публичный API
```

Дальше — `npm run lint:fsd`: Steiger проверит, что сегменты названы по
назначению, публичный API на месте и никто не импортирует слайс в обход `index.ts`.

## Ограничения

- В админке нет авторизации.
- Адрес API захардкожен (`http://localhost:3001`), переменных окружения нет.
- Главная и список проектов статические: изменения из админки появляются
  на сайте после пересборки.
- Картинки проектов через админку не редактируются.
